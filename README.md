# dsh-meta-theory

**让 AI 在动手之前，先把你的需求翻译成这一行的成熟方法。**

同一句话交给 AI，结果能差出一个档次，区别往往不在模型，而在有没有点名方法。你说「帮我算出哪队更可能赢」，它给你一段听起来合理的直觉判断；你说「按泊松分布建模进球数，算不动的部分用蒙特卡洛抽样，最后做敏感性检验」，它给你一个能检验、能复算、能指出假设失效点的概率分布。后者不是更聪明的模型，是更专业的提问。

问题是：**大多数人报不出那个方法的名字。** 不知道这个领域有成熟做法，就不会提；不会提，AI 就只按字面接活，交出一份排版整齐、语句通顺、但在内行眼里没按规范来的东西。

这个插件补的就是这一步。它不要求你知道方法叫什么，而是在你开口之后、AI 动手之前，先把任务对到该领域的方法体系上：一条主理论决定核心结构，零到两条辅助理论补住缺口，并给出一条能照着做的组合链路。做完之后，再回头校验这套方法是真的用了，还是只在开头报了几个名词。

## 它替你做三件事

**开工前，判断该不该讲方法。** 闲聊、翻译一段话、改个错别字、你明确说「只执行」——这些跳过。真正需要判断的任务（评估、创作、决策、规划、方案、诊断）才进入下一步。豁免条件只有四条，其余一律走流程，不靠模型那天心情好不好。

**给骨架，不给鸡汤。** 输出三样东西：主理论的三条判别问题（谁最直接描述核心对象、谁能独立成立、谁决定整体结构）、辅助理论的三道关（补哪个缺口、改变哪一步、删掉会漏什么）、以及一段能直接套的输出格式。辅助理论最多两条，覆盖完整就一条不加。

**写完验成色。** 这是它区别于「把提示词换个地方存」的地方：把技能里的自查表变成可执行的校验。主理论缺没缺、辅助理论是不是只有名字没过三关、两条以上理论有没有真的连成链、前提限制有没有写——逐条判，给分，指出必须改的地方。评价标准写在代码里，不看模型自觉。

## 工具

| 工具 | 作用 | 关键参数 |
|---|---|---|
| `meta_theory_brief` | 开工前：判豁免，不跳过就给骨架 | `task`、`domain`、`followUp` |
| `meta_theory_check` | 按 8 条翻车模式校验一棵理论树 | `main`、`aux`、`linkage`、`limits` |
| `meta_theory_status` | 插件／技能／规则三处真实落位状态 | — |
| `meta_theory_rule` | 输出规则文本，`write:true` 写进 AGENTS.md | `write` |

`aux` 两种写法都收。竖线串最省事，字段顺序是「名称 | 补足哪个缺口 | 在主理论之前／中／之后 | 不用会漏什么」：

```text
蒙特卡洛|模型无法解析求解时用抽样求分布|主模型之后|无法直接积分时拿不到分布
```

一次真实校验的返回（劣质树）：`ok:false`、`score:35`，逐条指出「蒙特卡洛：缺补足哪个缺口」「缺在主理论之前／中／之后使用」「缺不用它会漏什么」，外加「缺使用前提／限制」。把三条缺口补齐后同样输入返回 `ok:true`、`score:100`。

## 装上就带技能

apply 时把包内的 `assets/SKILL.md` 幂等投放到 `~/.dsh/skills/元理论检索/SKILL.md`。目标不存在就安装；内容 hash 命中本插件已知版本就升级；hash 不匹配（你手改过）就跳过并在状态里报告，绝不覆盖。技能正文 149 行，含完整流程、足球概率的主次组合示例与 8 条翻车自查。

## 校验判据

**错误（`ok=false`，必须改）**

- `E_MAIN_MISSING` 缺主理论
- `E_AUX_NAME_MISSING` 辅助理论缺名称
- `E_AUX_MISSING_GAP` 缺「补足哪个缺口」，过不了缺口测试
- `E_AUX_MISSING_WHEN` 缺「之前／中／之后」，排不出链路
- `E_AUX_MISSING_LOSS` 缺「不用会漏什么」，过不了删除测试
- `E_LINKAGE_MISSING` 两条以上理论却没有组合链路

**警告（不阻断，但会被点出来）**

- `W_AUX_OVER_BUDGET` 辅助理论超过 2 条
- `W_AUX_DUPLICATE` / `W_AUX_SAME_AS_MAIN` 同层重复
- `W_LINKAGE_NO_ORDER` 链路缺顺序词
- `W_LIMITS_MISSING` 缺使用前提／限制

只有主理论、不补辅助理论是**合法**的，技能本身允许辅助理论为 0 条，因此不会判失败。这是刻意的：不为了显得完整而堆砌。

## 安装

```bash
# 本地目录（开发）
dsh plugin --profile desktop add link:D:/DeepSeek-Work/dsh-meta-theory

# Release 里的 tgz
dsh plugin --profile desktop add https://github.com/<owner>/dsh-meta-theory/releases/download/v0.1.0/dsh-meta-theory-0.1.0.tgz

# npm（发布后）
dsh plugin --profile desktop add dsh-meta-theory
```

装完重启 DSH，工具出现在会话里，命令出现在输入框。

## 落位与幂等

- 技能文件：见上，三种分支，绝不静默覆盖。
- AGENTS.md：`## 11. 理论前置` 已存在则跳过；首次写入前生成 `.bak-<时间戳>`。
- 数据目录 `~/.dsh/meta-theory/`：`state.json` 加有界 `log.jsonl`，超 500 行自动裁到 300 行。

## 插件契约（踩坑记录，改代码前先看）

1. 工具必须带 `output { schema, render }`，否则 `tools.register()` 抛异常**且被静默吞掉**，现象是「插件加载成功但零工具」。
2. `apply()` 时 `tools` 服务可能尚未就绪：监听 `internal/service` 加 1.5 秒定时重试，12 次后放弃。
3. 工具返回值必须是 **lossless JSON**：`undefined`／`BigInt`／循环引用会让整条调用失败，统一走 `toLossless()`。
4. 不声明 `dsh.client`，因此不需要 `exports["./client"]`。这条成对契约漏写会触发宿主自愈、清空 profile 里的插件层。
5. Windows 下写文件一律 UTF-8 无 BOM：BOM 会让 profile 的 `package.json` 解析失败。

## 与技能的关系

技能负责「怎么写」，插件负责「该不该写、写完合不合格、装没装上」。本机若同时装了 `theory-term-injection`（事后按术语改写提示词）与 `meta-knowledge-lookup`（找词），优先级写在技能正文的「与已装技能的分工」一节：开工前的导航走本技能，产出后仍不达标才用注入法，找词降为内部动作。
